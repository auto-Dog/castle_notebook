# 0.9 开发说明

## 产品定位

面向算法、金融等工作者的 AI 辅助实时调试环境。核心价值是拆分端到端 AI 过程，将目的、输入、行为、输出和验证细化为可观察、可修改、可停止的单元，以此实现全局控制和透明性。

基础规划来源于仓库中的《CastleNotebook项目开发.pdf》，并纳入用户补充的研究调试定位与经典 Jupyter 界面要求。

## 0.9 交付范围

| 需求 | 实现与验收方式 |
| --- | --- |
| Notebook 展示 | 本地网页；Global、三种输入、配对输出；直角卡片与 In / Out 编号 |
| 项目工作区 | Notebook 绑定项目目录，可选择子项目；工具栏展示项目名称，检查器列出项目文件与当前源码预览 |
| Global Cell | 目的和约束即时编辑、自动保存；完整纳入 AI 输入 |
| Python Cell | 持久子进程、共享命名空间、最后表达式、stdout / traceback、结构化表格与可选图像 |
| Markdown Cell | 双击编辑、执行预览；禁用原始 HTML；记录时间戳 |
| Order Cell | 指令、必填输出契约、输出格式；后台直接调用本机 Claude；按 Session Name 在新终端打开最近一次对话（Windows） |
| 上文精简 | 逐个打包所有前置单元，固定字符预算；支持用户摘要；完整保留 Global 和当前输入 |
| AI harness | Markdown 输入文件、CLI 后台调用、流式事件、规范化最终回答、文件产物、严格 JSON 校验 |
| 运行控制 | 单步、顺序运行、停止、超时、重启内核；同一 Notebook 串行执行 |
| 证据追踪 | 每次执行保存输入版本、完整 prompt、指纹、输出、事件、耗时、状态及错误 |
| 项目文件变更 | Python / Order 执行前后比较项目文件内容指纹；回收新增、修改、删除的路径，失败或停止时也保留；明确扫描范围与不完整覆盖 |
| 从项目初始化 | 文件快照、只读 Agent 分析、结构校验、显式采用；生成代码不自动执行 |
| 持久化 | JSON 文档原子写入、版本冲突检查、刷新恢复、导出文档与运行产物 |

## 控制规则

- 用户定义 Global；AI 不自行改变已保存的全局约束。
- Notebook 是项目的交互界面。开发或修复步骤在项目源码与测试中落地，Python 单元导入项目模块进行验证；只读分析及初始化遵循当前指令。每次输入都带入项目工作区说明，旧的自定义模板自动兼容。
- 每个 Order 只负责当前步骤，必须声明预期输出。输出格式校验和领域结论验证是两个不同层次。
- 每个 Order 将完整输入写入 `.castle/prompts/input<运行ID>.md`，使用 `claude -p "请读取输入文件并完成任务" -n "ID<运行ID>"`，完整继承本机 Claude 的模型、工具、MCP 和权限配置；仅增加网页所需的流式输出参数。旧 LLM / Agent 字段不再限制工具。
- 上游输入、Global 或单元顺序改变后，相关下游旧输出仍保留，但退出有效证据集合。
- Python 共享内存符合 Notebook 工作方式：失败前的赋值可能保留，上游重跑也可能留下旧变量。检查器明确提示；内核重启支持从头验证。
- 代码取消或超时后销毁该内核，避免把未知状态继续用于调试。
- Global 在运行中保持可编辑，使用独立版本保存；当前执行保留启动时快照，若 Global 已变化则将返回结果标记失效。其他输入单元在运行中锁定。
- 记录模型的可观察响应和工具行为，不将流式中间文本冒充最终结论。

## 上下文策略

每次打包默认包含 Global、全部前置单元的有界输入摘要、仍然有效的执行结果摘要、当前 Python 变量的有界元数据、当前输入和输出契约。只使用当前单元之前的内容。项目的 `.castle/context.json` 可开关各段、编辑 harness 文字与模板顺序，并调整预算；修改后在下一次预览或执行时重新加载，运行记录保存配置快照与指纹。

总预算默认为 48,000 字符。开启历史精简时，前置单元按策略分配空间，用户摘要可替代默认输入截取；当前输入与已启用的全局约束不能完整纳入时拒绝执行并提示拆分。关闭历史精简后超过预算也会明确报错。展示字符数、粗略 token 估计和 SHA-256。预览与执行使用同一个打包函数；实际执行快照独立存档。

精简是确定性的文本裁剪，不依赖隐藏的二次 LLM 调用。0.9 不自动进行事实核验或语义压缩质量评估。

## 架构

```text
项目工作区：源码 / 测试 / 数据 / .castle 交互与执行证据
              |
Notebook 网页：Global / STEP Input / Run / STEP Output
              |
本机 API：项目绑定 / 上下文打包 / 文档版本与失效规则
              |
Python worker / Claude CLI（在绑定项目目录中执行）
              |
读取、开发和验证项目代码 -> 回收回答、文件变更、事件和运行记录
```

Python 标准库实现本地 HTTP、子进程控制、JSON 持久化和测试；前端使用原生 JavaScript / CSS。每个 Notebook 独立 Python 进程；每个 Order 为新的命名 Claude 调用，输入来自保存的显式上下文，而不是隐藏续聊状态。

Python 内核将项目根目录加入模块搜索路径。项目模块仍遵循 Python 的导入缓存规则，修改后需显式重新加载或重启内核。执行期间观测到项目文件变化时，本 Notebook 其他已有 Python / Order 结果均标记失效；这不构成外部编辑器或跨 Notebook 的文件依赖追踪。

## 界面约束

- 白底、直角边框、经典 Notebook 输入输出布局。
- 常驻区域只保留文档标题、菜单、工具栏和实际单元内容。
- 代码语法高亮，Markdown 文本直接排版。
- 上下文、变量、时间戳和历史记录放入按需检查器。
- 状态、提示和帮助按操作需要出现，不在每个卡片重复解释产品理念。

## 验收与边界

自动化检查真实 Python 运行、共享变量、格式化输出、错误保留、单元串行、取消/超时、重启恢复、上下文预算/失效、JSON 契约、初始化采用、HTTP 写保护及 SSE 重放。浏览器检查工具栏执行、Markdown 编辑、保存、变量面板、经典布局与窄屏。

Claude 协议测试使用可控子进程夹具；真实云端可用性由本机 Claude 的认证、网络和额度共同决定。0.9 不提供完整环境封存、操作系统沙箱或远程多人协作。
